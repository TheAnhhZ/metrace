# Deployment (single machine)

metrace is designed to run on one laptop for a demo. All ports are bound to
`127.0.0.1`; only the gateway (`:9080`) is published.

## Requirements

- Docker Engine with Compose v2 and BuildKit (Docker Desktop, or Colima on
  Apple Silicon: `colima start --cpu 4 --memory 6`).
- GNU Make, Bash, `curl`, `jq`. For the CLI and tests: [uv](https://docs.astral.sh/uv/).
- About 3 GB of RAM for the stack (Keycloak ~0.6 GB, Flowable ~0.4 GB).

## First start

```bash
make init                     # .env with random secrets (never committed)
docker compose up -d --wait   # builds images, runs migrate, kc-bootstrap and seed
scripts/smoke-core.sh         # optional, needs `KC_OVERLAYS=test` (see below)
```

Order on start: `postgres` → `keycloak`, `seaweedfs`, `flowable` →
one-shots `migrate` (schema + bucket), `kc-bootstrap` (organizations,
memberships, mappers, overlays), `seed` (demo data relative to now) → `api`,
`worker` → `web` → `apisix`. One-shots are idempotent; running `up` again is safe.

## Configuration (`.env`)

| Variable | Meaning |
|---|---|
| `*_PASSWORD`, `*_SECRET`, `S3_*` | Generated by `make init` |
| `DEMO_USER_PASSWORD` | Password of every demo account |
| `KC_OVERLAYS` | Empty for demos; `test` adds the CI-only client `metrace-test` |
| `RATE_LIMIT_API_PER_MIN`, `RATE_LIMIT_READINGS_PER_MIN` | Gateway limits per token |
| `INCIDENT_TRIAGE_SLA`, `COLDCHAIN_CHECK_SLA` | Escalation timers (ISO 8601) |
| `COMPLAINT_SLA_OVERRIDE_MINUTES` | Shorten complaint deadlines for a demo |
| `LLM_BASE_URL` | Optional local model for report drafts (`scripts/ai-up.sh`) |

## Operations

```bash
make demo-reset                          # fresh "today" in ~10 s (keeps master data)
scripts/demo-reset.sh baseline,outbreak  # plus the outbreak complaints
make dev-ports                           # also publish postgres/keycloak/flowable for tests
make reset                               # delete ALL data volumes
```

Changing the realm file after the first start: the import skips an existing
realm. `kc-bootstrap` re-applies organizations, memberships and client mappers;
anything else needs `make reset`.

If you recreate a single upstream container (`docker compose up -d api`), also
restart the gateway (`docker compose restart apisix`): APISIX resolves upstream
names when it loads its configuration. A full `docker compose up -d` does this
automatically.

## Clean machine check

```bash
colima start -p clean --cpu 4 --memory 6
git clone <repository> metrace && cd metrace
make init && KC_OVERLAYS=test docker compose up -d --wait && scripts/smoke-core.sh
```
