# Contributing to metrace

Thanks for helping. A few rules keep the project healthy and fully open source.

## Workflow

1. Open or pick an issue. Keep work items small (a few hours).
2. Branch from `main`, open a pull request, link the issue.
3. CI must be green: ruff, `reuse lint`, gitleaks, tests.
4. Pull requests are squash-merged. Use [Conventional Commits](https://www.conventionalcommits.org/)
   for titles (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`).
5. Update `CHANGELOG.md` under `Unreleased` for user-visible changes.

## Licensing rules

- All code is Apache-2.0. Every new file needs an SPDX header:

  ```
  SPDX-FileCopyrightText: The metrace Authors
  SPDX-License-Identifier: Apache-2.0
  ```

  Files that cannot hold a comment (JSON, lock files) are covered by `REUSE.toml`.
- New dependencies, container images and model weights must use an OSI-approved
  license. Source-available licenses (BUSL, SSPL, FSL, Elastic, Commons Clause)
  are not accepted. Mention every new dependency in the pull request.
- Add yourself to `AUTHORS` in your first pull request.

## Secrets

Never commit secrets. `.env` is generated by `make init` and ignored by git.
Install the pre-commit hooks (`pre-commit install`) so gitleaks runs locally.

## Local setup

See the README quick start. Python code lives in `services/api` (uv project),
run `make lint` and `make test` before pushing.
